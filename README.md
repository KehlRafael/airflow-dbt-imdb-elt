# ELT with Airflow and dbt Core on Postgres

This is a modified version of the [Official Apache Airflow 3.0.6 Docker Compose](https://airflow.apache.org/docs/apache-airflow/3.0.6/howto/docker-compose/index.html) to include `pgAdmin` and a dedicated data warehouse using `pgduckdb` (Postgres with DuckDB extension) to allow the user to run the project's DAGs as well as query the data warehouse to inspect the data generated by the ELT process without relying on any other software installed in the machine.

This is not a production-ready container image. It has many issues, such as unencrypted and default credentials. The goal of this project is to provide a starting point for those that want to learn more about dbt and Airflow.

## What This Project Does

This project demonstrates a complete **ELT (Extract, Load, Transform) pipeline** that analyzes TV series episode ratings from IMDb. You'll build a working data pipeline that:

1. **Extracts** - Downloads real IMDb datasets (title information, episode details, and ratings)
2. **Loads** - Ingests raw data into a PostgreSQL data warehouse
3. **Transforms** - Uses dbt to clean and structure the data into analytics-ready tables
4. **Orchestrates** - Automates everything with Apache Airflow

By the end, you'll have a data warehouse with organized layers:
- **Staging layer** (`stg_*`): Cleaned TV series and episode data
- **Fact tables** (`fact_*`): Episode and series ratings with vote counts
- **Dimension tables** (`dim_*`): Pre-calculated best and worst episodes for each series

### Example Questions You Can Answer

Once the pipeline runs successfully, you can query the data warehouse to discover:
- "What is the highest-rated episode of Breaking Bad?"
- "Which TV series have the most dramatic quality drops between best and worst episodes?"
- "What are the top 10 best-rated TV episodes of all time?"
- "How many votes does each episode have, and how reliable are the ratings?"

## Technologies Used

This project combines several modern data engineering tools. Here's what each one does:

### Core Technologies

- **[Apache Airflow](https://airflow.apache.org/)** - Workflow orchestration platform that schedules, monitors, and manages data pipelines. Think of it as a sophisticated task scheduler that can run Python code, bash commands, and handle dependencies between tasks.

- **[dbt (data build tool)](https://docs.getdbt.com/)** - SQL-based transformation framework for analytics.

- **[PostgreSQL](https://www.postgresql.org/)** - Open-source relational database serving as our data warehouse. We use version 16 with special extensions:
  - **[pg_duckdb](https://github.com/duckdb/pg_duckdb)** - Integrates DuckDB's fast analytical query engine into PostgreSQL, even allowing for file reading

- **[Docker](https://www.docker.com/)** - Containerization platform that packages all software and dependencies so everything runs consistently on any machine without manual installation.

### Supporting Tools

- **[pgAdmin](https://www.pgadmin.org/)** - Web-based database management tool for querying and exploring your data warehouse visually.

- **[uv](https://docs.astral.sh/uv/)** - Fast Python package manager for installing dbt and its dependencies locally.

- **[Astronomer Cosmos](https://astronomer.github.io/astronomer-cosmos/)** - Library that provides native dbt integration in Airflow, turning each dbt model into an Airflow task for better observability.

### Why ELT?

**ELT (Extract, Load, Transform)** loads raw data into the warehouse first, then transforms it using SQL. This differs from traditional **ETL (Extract, Transform, Load)** which transforms data before loading. ELT is popular in modern data warehouses because:
- Leverages the warehouse's computing power for transformations
- Raw data is preserved for auditing and reprocessing
- Faster initial data loading
- More flexible for iterative analysis

## Get Started
First clone the repository into your local machine:
```
git clone https://github.com/KehlRafael/airflow-dbt-imdb-elt.git
cd airflow-dbt-imdb-elt
```

 An optional step, in case you want to serve (access via a web page) the `dbt` documentation, is to install the project dependencies in a virtual environment. To do that, use `uv` to create the project's virtual environment and then activate it:
```
uv sync
source .venv/bin/activate
```

This will allow you to use `dbt` commands locally, not only from inside your DAGs.

### Configuration
Before running the containers, you can customize the environment by editing the [.env](.env) file. Key configuration options include:

- **Airflow credentials**: Change `_AIRFLOW_WWW_USER_USERNAME` and `_AIRFLOW_WWW_USER_PASSWORD` for custom Airflow UI login
- **Data warehouse port**: Change `WAREHOUSE_PORT` if you have port 5432 in use (default: 5432)
- **Database credentials**: Modify `WAREHOUSE_POSTGRES_USER`, `WAREHOUSE_POSTGRES_PASSWORD`, etc. for custom database credentials
- **pgAdmin credentials**: Update `PGADMIN_DEFAULT_EMAIL` and `PGADMIN_DEFAULT_PASSWORD` for custom pgAdmin access

**Important**: If you change database credentials, you must also update:
- [dbt/imdb_ratings/profiles.yml](dbt/imdb_ratings/profiles.yml)
- [postgres/pgpass](postgres/pgpass)
- [postgres/servers.json](postgres/servers.json)

### Running the containers
To run the containers specified in the [docker-compose.yml](docker-compose.yml) file you can simply run:
```
docker compose -p imdb_ratings up -d
```
This command will automatically build the custom Docker images (Airflow with dbt/Cosmos and PostgreSQL with extensions) on first run and then start all services. All containers will be listed under the `imdb_ratings` project.

### Accessing the UI
To access the Airflow UI, you must:
- Open the Airflow UI at [http://localhost:8080/](http://localhost:8080/)
- Username: airflow
- Password: airflow

These are the default values in the [docker-compose.yml](docker-compose.yml). They can be changed by updating the variables listed above in the [.env](.env) file.

To access the `pgAdmin` UI, you must:
- Open the `pgAdmin` UI at [http://localhost:8888/](http://localhost:8888/)
- Email: admin@admin.com
- Password: admin

These are the default values in the [docker-compose.yml](docker-compose.yml). They can be changed by updating the variables listed above in the [.env](.env) file.

### Connecting to the data warehouse

The data warehouse (`pgduckdb_warehouse`) default connection details are:
- **Host**: localhost
- **Port**: 5432
- **Database**: dwh
- **Username**: postgres
- **Password**: postgres

You can connect using pgAdmin (see [Accessing the UI](#accessing-the-ui) section above) or any other database client. The [postgres/pgpass](postgres/pgpass) and [postgres/servers.json](postgres/servers.json) files contain connection string formats for various tools. All default values are configurable in the [.env](.env) file.

### Extracting and loading the IMDb datasets

Before running any transformations, you need to extract and load the raw IMDb data using the [extract_and_load_datasets](./airflow/dags/extract_and_load_datasets.py) DAG. This DAG performs the following steps:

1. **Downloads IMDb datasets** from [https://datasets.imdbws.com/](https://datasets.imdbws.com/)
   - `title.basics.tsv.gz` - Basic information about titles (movies, TV shows, etc.)
   - `title.episode.tsv.gz` - Episode information for TV series
   - `title.ratings.tsv.gz` - IMDb ratings and vote counts
2. **Unzips the datasets** and removes the compressed files
3. **Sets up database tables** using [sql/setup_imdb_tables.sql](./sql/setup_imdb_tables.sql)
4. **Ingests the data** into the data warehouse using [sql/ingest_imdb_tables.sql](./sql/ingest_imdb_tables.sql)

This DAG accepts two optional parameters that can be configured when triggering it manually from the Airflow UI:

- **`rewrite_files`** (boolean, default: `false`)
  - Set to `true` to re-download datasets even if they already exist in the `/data` folder
  - Set to `false` (default) to skip downloading if files are already present
  - Useful when you want to refresh the data with the latest IMDb datasets

- **`db_conn_var`** (string, default: `AIRFLOW_CONN_PGDUCKDB_WAREHOUSE`)
  - The environment variable name containing the database connection string
  - Default points to the data warehouse configured in docker-compose.yml
  - Only change this if you want to use a different database connection

### Running dbt transformations

This project provides two DAG options for executing dbt transformations, both located in [airflow/dags](./airflow/dags):

1. **`run_imdb_ratings_dbt_bash.py`** - Traditional approach using BashOperator to execute dbt commands. This gives you full control over the dbt CLI commands and is useful for learning how dbt commands work, but has no error handling or alerting.

2. **`run_imdb_ratings_dbt_cosmos.py`** - Modern, and recommended, approach using [Astronomer Cosmos](https://astronomer.github.io/astronomer-cosmos/) (version 1.11.2), which provides native dbt integration in Airflow. This automatically generates Airflow tasks for each dbt model, enabling better observability, task-level retries, and parallel execution of independent models.

Both DAGs accomplish the same goal - transforming the raw IMDb data into analytics-ready tables. Choose the one that best fits your learning goals or operational needs. You can enable either or both DAGs in the Airflow UI.

### Serving dbt documentation

Make sure both the [extract_and_load_datasets](./airflow/dags/extract_and_load_datasets.py) and [run_imdb_ratings_bash](./airflow/dags/run_imdb_ratings_dbt_bash.py) or [run_imdb_ratings_cosmos](./airflow/dags/run_imdb_ratings_dbt_cosmos.py) DAGs were already executed successfully in Airflow. After that, run the following commands from the root of this project:
```
cd ./dbt/imdb_ratings
uv run dbt docs serve --port 8001 --profiles-dir .
```
With that, documentation will be available at [http://localhost:8001/](http://localhost:8001/).

### Stopping and removing images
To stop the containers run:
```
docker compose -p imdb_ratings stop
```
To tear down the environment run:
```
docker compose -p imdb_ratings down
```
You can add the `-v` and `--rmi local` flags at the end to also remove volumes and images, respectively, that are associated with the project.
